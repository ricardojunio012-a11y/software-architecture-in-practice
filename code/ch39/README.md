# Chapter 39: technical debt, hotspots, and change coupling

Lab for chapter 39 of *Software Architecture in Practice*.

Inside the container, the lab creates a real git repository with 18 months of Morada's simulated history (January 2025 to June 2026): 389 commits by 8 people, with fixed authors and dates, generated by a draw with a fixed seed and written with `git fast-import`. That history holds a hot, complex module (billing charges) and a hidden change coupling: the bookings rule reads a Billing table without importing anything from it. A TypeScript tool reads the history with `git log --numstat` and computes the hotspots (change frequency × complexity from indentation), the pairs of files that change together, and the business case for paying down the largest debt.

| Version | What it does |
|---|---|
| `history` | Generates the repository and shows the summary and the latest commits |
| `hotspots` | Lists the files by priority: revisions × complexity |
| `coupling` | Lists the pairs that change together and says whether the code shows the link (import) |
| `business-case` | Computes the interest on the top hotspot and compares three options over 12 and 24 months |

The hours of each change come from an `Hours:` trailer in the commits, which stands in for the time logged on tasks. The cost assumptions ($150 per hour, $1,200 per person-day, the paydown effort, the price and adoption of the new feature) are in `node/assumptions.json`.

## Prerequisite

Docker with Docker Compose. This lab has only the TypeScript version and starts no other services.

## Walkthrough

```bash
docker compose run --rm app history
docker compose run --rm tools verify history
docker compose run --rm app hotspots
docker compose run --rm tools verify hotspots
docker compose run --rm app coupling
docker compose run --rm tools verify coupling
docker compose run --rm app business-case
docker compose run --rm tools verify business-case
docker compose run --rm app tests
```

## On your own repository

The same analysis runs on any git repository, mounted read-only (in Git Bash, prefix the command with `MSYS_NO_PATHCONV=1`):

```bash
docker compose run --rm -v /path/to/repository:/repo:ro app analyze /repo
```

## Try it

- Change `MAX_FILES` in `metrics.ts` to 100 and see what the formatting commit does to the revisions.
- In `history.ts`, lower from 0.8 to 0.3 the chance that the bookings rule changes together with the unit's billing status.
- In `assumptions.json`, change the expected interest reduction and the paydown effort until "pay first" becomes the cheapest option over 24 months.
